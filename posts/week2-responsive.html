第二周：手机上那条横向滚动条是怎么消失的

2026 年 10 月 10 日 #CSS #布局 #响应式

第一周结束的时候，我的页面在电脑上看着还行。切到手机上一看：导航竖着排还带小圆点，表单挤成一行，页面能横向拖动——也就是说，内容比屏幕宽，右边有一截被推出了视野外。

第二周解决的就是这件事。这一周的收获比第一周大得多，因为它回答的是「为什么」。

Flexbox：把一组东西排成一行

导航为什么是竖的？因为 <li> 默认是块级元素，一个占一整行。

Flexbox 就是专门解决「把一组东西按行或按列自动排好」的工具。它只有一条核心规则，但这条规则最容易搞反：

display: flex 写在「装这些元素的父元素」身上，不是写在每个子元素身上。

对导航来说，父元素是 <ul>，子元素才是那几个 <li>：

nav ul {
  display: flex;      /* 让 li 横过来 */
  list-style: none;   /* 去掉小圆点 */
  padding: 0;         /* 去掉浏览器默认的缩进 */
  gap: 20px;          /* 项与项之间的间距 */
}

加了 flex 之后，会多出两个「方向」的概念：

  • 主轴（main axis）：元素排布的方向，默认横向
  • 交叉轴（cross axis）：和主轴垂直的那个方向

所有对齐属性都在回答「沿哪根轴对齐」：

属性管哪根轴常用值
justify-content主轴flex-start / center / space-between
align-items交叉轴center / flex-start
flex-direction换主轴方向row（默认）/ column
flex-wrap放不下时怎么办nowrap（默认，硬挤）/ wrap（换行）
gap相邻元素之间的间距20px

gap 是这一组里最省事的一个属性。在它出现之前，做间距要在每个子元素上用 margin，然后还要想办法去掉最后一个的多余边距。现在一行就够。

第一天被我忽略、第二天才用上的是 flex-direction: column——它能把主轴从横向改成纵向，于是「表单里每个标签和输入框各占一行」就变成了一行代码的事。

Grid：管两个方向

Flexbox 只能管一个方向：一行，或者一列。要做「卡片墙」这种行列都要管的布局，用 Grid：

.grid {
  display: grid;
  grid-template-columns: repeat(3, 1fr);   /* 3 列，每列等宽 */
  gap: 16px;
}

1fr 是 Grid 专用的单位，意思是「把剩余空间按比例分一份」。repeat(3, 1fr) 就是「重复 3 次 1fr」，写成三遍 1fr 1fr 1fr 也一样。

判断该用哪个，我现在用的标准是：只需要排成一行或一列，用 Flexbox；要同时管行和列，用 Grid。

四种尺寸写法，决定了手机上会不会横向滚动

这是整周最重要的一节。同一个宽度有四种写法，效果完全不同：

写法含义什么时候用
400px固定 400 像素小图标、边框这类确定的尺寸
100%占父元素宽度的 100%图片、容器，让它跟着父元素走
2rem相对根字号，默认 1rem = 16px字号、间距
max-width: 400px最多 400px，窄了会跟着缩卡片、正文容器

关键在于这一对的区别：

width: 400px;        /* 死命令：屏幕只有 360px 它也要占 400px → 溢出 → 横向滚动条 */
max-width: 400px;    /* 上限：屏幕 360px 时它缩到 360px → 不溢出 */

我原来那个卡片写的是 width: 400px，改成 max-width 之后，横向滚动条当场消失。

但也不能一刀切全改。头像的 width: 120px 就该留着——头像是一个确定的尺寸，你不会希望它在小屏上变小。规则是：确定要多大用 px，不确定、要跟着容器走用 max-width 或 %。

媒体查询：让页面「看宽度下菜」

max-width 只能救单个元素。但有些调整是整套的：手机上字号小一点、间距密一点、卡片从三列变一列。

/* 基础样式写在上面（这是电脑上的样子） */

@media (max-width: 768px) {
  /* 屏幕宽度 ≤ 768px 时，这里面的规则才生效 */
  body { font-size: 16px; }
  .grid { grid-template-columns: 1fr; }
}

它有两个前提，缺一个就完全不生效，而且都不报错：

  1. <head> 里必须有 <meta name="viewport" content="width=device-width, initial-scale=1">
  2. 媒体查询必须写在基础样式之后——CSS 里后写的规则覆盖先写的，写在前面会被覆盖掉

所以我的做法是：@media 永远放在 style.css 的最后。不是因为它必须在最后，而是因为这样不会犯错。

图片：另一大来源

一张 800px 宽的图塞进 375px 的屏幕，直接撑破。一行解决：

img {
  max-width: 100%;
}

意思是「图片最宽不超过它所在容器的宽度」，容器窄它就跟着缩。这一行加上之后，以后不管往页面里丢多大的图都不会出问题。

最后一件：读起来舒服

这一周还学了一件和「布局」不那么直接相关、但可能更重要的事——正文排版：

body {
  font-size: 17px;    /* 正文不低于 16px */
  line-height: 1.8;   /* 行高 1.7～1.8 */
}

.article {
  max-width: 36em;    /* 每行约 36 个字 */
  margin: 0 auto;
  padding: 0 1rem;
}

这里有两个说法值得记住。行高不带单位时，它表示「字号的倍数」，写 1.8 比写 28.8px 好，因为字号一变，行高会跟着变。

1em 等于当前元素的字号。36em 在 16px 字号下大约是 576px，正好是一行 36 个汉字左右的宽度。行太长的坏处是：眼睛看完一行，要费力去找下一行的开头，读久了会累。

这一周的验收

我用 DevTools 的设备模拟（Ctrl + Shift + M）把 375px（iPhone）、768px（iPad）、1024px 以上三种宽度各看了一遍，确认：

  • 没有横向滚动条
  • 导航都在一行内
  • 卡片从三列平滑变成一列
  • 拖浏览器窗口从最宽到最窄，不会突然挤成一团

下周开始学 JavaScript。这一周结束时主页看起来和之前差不多，但它现在是「能缩」的——这是一件看不见、但决定手机端体验的事。

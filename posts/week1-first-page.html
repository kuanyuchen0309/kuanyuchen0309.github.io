第一周：从一张白纸到一个能上线的主页

2026 年 10 月 3 日 #HTML #CSS #Git

七天前，我的屏幕上是空的。七天后，我有一个网址，手机和电脑都能打开，里面有头像、有自我介绍、有导航、有表单，还有一个我自己写的页脚。

这一周真正学到的东西，比我预想的要少——但少的那部分，是能用的。

第一天：页面是「一堆盒子」

HTML 的第一个认知转变是：它不是「排版」，是「标注」。你写下的每一个标签都在说「这一块是什么」，而不是「这一块长什么样」。

最开始的骨架长这样：

<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>我的主页</title>
</head>
<body>
  <h1>你好</h1>
</body>
</html>

这里面有两行当时完全看不懂、但后来发现少一行就出事的：

  • <meta charset="utf-8"> —— 告诉浏览器「用 UTF-8 来解码这些字节」。没有它，中文会变成乱码。它不是可选的美化，是必需品。
  • <meta name="viewport" ...> —— 手机适配的前提。没有它，手机打开会把整个页面缩成很小的一坨，第二周要学的响应式全都不会生效。

然后是几个基本标签：<h1> 到 <h6> 是标题，<p> 是段落，<a> 是链接，<img> 是图片，<ul> 加 <li> 是无序列表，<div> 是一个没有外观的盒子。

有一个细节我记到现在：<img> 没有闭合标签。别的标签都是 <p>...</p> 成对出现，只有它自己一个就结束了，因为它里面不装别的东西。

第二天：CSS 是「选中谁，改什么」

CSS 的规则结构很简单：一个选择器，一对花括号，里面一行行「属性: 值;」。

h1 { color: #0b6bcb; }        /* 标签选择器：所有 h1 */
.avatar { border-radius: 50%; } /* class 选择器：class="avatar" 的元素 */
#top { font-size: 20px; }       /* id 选择器：id="top" 的元素 */

当时最容易混的是这句话，我抄在笔记第一行：

点 = 找 class。选标签不写点。

写在 HTML 里的时候不加点（class="avatar"），写在 CSS 里的时候加点（.avatar）。多一个点、少一个点，规则就静默失效——页面没有任何反应，也不会报错。

第三天：八成「图不显示」都是路径问题

图片的地址有两种写法：

写法含义
img/me.jpg 或 ./img/me.jpg从当前文件所在文件夹往下找
../me.jpg回到上一级目录再找
https://...网上的绝对地址
D:\...永远不要用。换台电脑就失效，上线之后更是必然失效

这里有一个我亲眼看了一遍才记住的坑：Windows 不区分文件名大小写，但线上服务器（Linux）区分。把 me.jpg 改成 Me.JPG，本地照样显示，推上去图片就消失了。所以文件名统一用小写加连字符，是给自己省事。

第四天：盒模型

网页里每个元素都是一个盒子，从里到外四层：

┌─────────────────────────┐
│         margin          │  ← 和其他元素之间的距离
│  ┌───────────────────┐  │
│  │      border       │  │  ← 边框
│  │  ┌─────────────┐  │  │
│  │  │   padding   │  │  │  ← 内容和边框之间的距离
│  │  │   content   │  │  │  ← 文字/图片本身
│  │  └─────────────┘  │  │
│  └───────────────────┘  │
└─────────────────────────┘

这里有一行「抄上就行」的代码，到第四天才明白它的意义：

* {
  box-sizing: border-box;
}

默认情况下，width: 100% 指的是内容宽度，再加上内边距和边框就会超出屏幕。加上这行之后，宽度把 padding 和 border 一起算进去，符合直觉。* 是通配选择器，意思是「页面上的每一个元素」。

另一个当天觉得很神奇的东西是居中：

.card {
  max-width: 520px;
  margin: 40px auto;
}

auto 就是水平居中的关键——但前提是这个盒子必须有一个比父容器窄的宽度，否则「自动」没有可分配的余量。

第五天：给盒子起名字

前几天我用 <div> 装一切。这一天换成了「有名字的盒子」：

标签用途
<header>页头
<nav>导航栏
<main>页面主体，一页一个
<section>主体里的一个区块
<footer>页脚

视觉上它们和 <div> 一模一样，什么都不多不少。区别是浏览器和读屏软件能看懂这个结构——这对看不见页面的人很重要，对搜索引擎也一样。

第六天：DevTools 是这一周最值钱的东西

按 F12 打开。两个面板要一直留着：

  • Elements：点左上角的小箭头，再去页面上点任意元素，右边 Styles 面板会列出它身上所有的样式，而且每条规则右边都标着它来自哪个文件、第几行（比如 style.css:12）。
  • Console：以后所有 JavaScript 的报错都在这里。

最有用的一点：在面板里改颜色、改字号，页面立刻跟着变，刷新就恢复。改不坏。知道这一点之后，我才敢随便试。

第七天：上线

推送只有三条命令：

git add .
git commit -m "第 1 周：个人主页"
git push

第一次要多几步：初始化仓库、改分支名为 main、连上远程地址、推上去，然后在 GitHub 仓库的 Settings → Pages 里把 Source 选成 main 分支的 / (root) 目录。等一两分钟，就会拿到一个 https://用户名.github.io/仓库名/ 的网址。

第一次 push 会弹出浏览器让你登录 GitHub 授权。那不是让你输密码——GitHub 早就不允许用账号密码推送了。

这一周最该记住的三句话

  1. CSS 写错了不会报错，只是没效果。所以「没反应」的时候，第一件事是按 Ctrl + F5 强制刷新，第二件事是去 Elements 面板看那条规则到底在不在。
  2. 中文乱码先查 <meta charset>。不是缺了它，就是它写得太靠后了（这件事我后来专门写了一篇）。
  3. 文件名全部小写加连字符。本地无所谓，线上是 Linux，区分大小写。

下周要做的是让这个页面在手机上真正排布得像样，而不只是「能看」。
